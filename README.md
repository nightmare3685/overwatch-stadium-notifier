# Overwatch Stadium Notifier

**音声処理はすべてPC内。ゲームの音を外部に送らず、マッチ成立をお知らせ。**

Overwatchのマッチ成立音を、その場で解析するWindows用ツールです。YouTubeを見ていても、別ウィンドウで作業していても、Overwatchだけの音を監視します。

- **ローカルで解析** — 音声をサーバーやクラウドAIへ送信しません。
- **OWだけを監視** — YouTube・Discordなど別アプリの再生音を除外します。
- **マイク不要** — ゲームが再生する音をWindowsから取得します。
- **音源ファイル不要** — 検知用の特徴データを同梱。利用者による録音の準備は不要です。
- **音声ファイルを保存しない** — 監視中の音は短いメモリ内バッファで処理します。

現在は試用版です。検知結果はアプリ内に表示します。任意でDiscord・LINEへの通知を有効にできます。

**動作確認はSteam版Overwatchのみです。Battle.net版は未検証です。**

## インストーラー不要 — ZIPを展開して起動

**検知機能はOverwatch起動中のみ利用できます。** ゲームが起動していない場合は「Overwatchを起動してください」と表示します。

本ツール専用のインストーラーはありません。現在のv0.1.0はPythonが必要で、初回起動時に展開先へ専用の仮想環境と依存パッケージを作成します。Python不要のEXE配布版ではありません。

1. 配布ZIPを展開します。
2. `start.bat` をダブルクリックします。
3. Overwatchを起動して「検知開始」を押します。
4. 音を検知すると、検知画面に切り替わり「マッチが見つかりました！」を大きく表示します。10秒後に「マッチ成立音を検知中…」へ戻り、「最後にマッチングした時間」は残ります（検知を停止した場合は「停止中」）。最終時刻は今回のアプリ起動中に検知した時刻です。

音声取得中は同じ場所の秒数だけが増えます。音量・一致度・検知履歴は「詳細ログ」タブで確認できます。音声は録音ファイルとして保存しません。

画面上部の **Language / 言語** で **JPN / ENG** を切り替えられます。監視を止めずに表示言語を変更でき、経過時間や通知の残り時間は維持されます。画面内のログ履歴も切り替わりますが、保存済みの診断ログは書き換えません。表示言語の変更は検知用の効果音を変更しません。

終了するときは「停止」を押すか、ウィンドウを閉じてください。ゲームを再起動したときは、検知も開始し直してください。

### 必要な環境

動作確認済みの配信プラットフォームは **Steam版のみ** です。Battle.net版の動作は未確認です。

- 64-bit Windows 11（音声取得APIはWindowsビルド20348以降に対応）
- Python 3.10以降（Tkinter付き）
- Windows付属の.NET Framework 4.x

**初回セットアップにはインターネット接続が必要です。** `start.bat` が専用の仮想環境にNumPyを取得します。準備後の音声取得・解析・アプリ内表示はローカルで動作します。Discord・LINEのテスト送信時、または通知を有効にして検知した場合のみ、通知文と時刻を指定サービスへ送ります。Overwatch本体の通信は別です。

## Discord通知

1. 「Discord設定」タブのWebhook URL欄に、DiscordでコピーしたURLを貼り付けます。
2. 「テスト送信」を押して、送信先チャンネルに届くことを確認します。ゲームの起動は不要です。
3. 「検知時にDiscordへ送信する」をオンにします。
4. Overwatchを起動して「検知開始」を押します。

通知文・検知時刻・任意のメンション先ユーザーIDを送信し、音声・一致度・診断ログは送信しません。通常のテキストチャンネル向けです。自動通知は30秒間の重複送信を抑制します。送信に失敗した場合は画面に表示し、自動再送はしません。テスト送信はチェックがオフでも送信します。

自分にメンションする場合は「自分のDiscordユーザーID（任意）」に数字のIDを入力してください。Discordの「ユーザー設定 → 詳細設定 → 開発者モード」をオンにし、自分のプロフィールのメニューから「ユーザーIDをコピー」で取得できます（[公式手順](https://support.discord.com/hc/ja/articles/206346498)）。テスト送信にもメンションが付きます。空欄ならメンションしません。IDは起動中のみ保持し、`webhook.txt` にはURLだけを書いてください。

指定したユーザー1人へのメンションだけを許可し、everyone・here・ロール宛てのメンションは使いません。メンションがあっても端末やDiscordの通知設定によってプッシュ通知が出ない場合があります。

URLは伏せ字で表示し、ログには保存しません。自動通知は起動ごとにオンにしてください。スマートフォンのプッシュ通知はDiscord側の通知設定にも依存します。

### webhook.txtから読み込む

`start.bat` と同じフォルダに `webhook.txt` を作り、Webhook URLだけを1行で書いてUTF-8で保存すると、次回起動時に入力欄へ読み込みます。ファイルを編集した後は「webhook.txtを再読み込み」でも更新できます。ファイルがない場合は直接入力できます。入力欄の編集はファイルへ書き戻しません。

`webhook.txt` はURLを平文で含む個人用ファイルです。他の人に共有しないでください。Git管理と `build-package.ps1` で作る配布ZIPからは除外しています。

## LINE通知（Messaging API）

1. LINE公式アカウントでMessaging APIを有効にし、LINE Developersでそのチャネルを開きます。
2. 「Messaging API設定」でチャネルアクセストークン（長期）を発行します。Channel IDやChannel secretではありません。
3. 「チャネル基本設定」の「あなたのユーザーID」（Uから始まるID）を確認します。通常のLINE IDとは別です。表示にはビジネスIDとLINEアカウントの連携が必要です。
4. 公式アカウントを自分のLINEで友だちに追加します。
5. アプリの「LINE設定」にトークンとユーザーIDを入力し、テスト送信で到着を確認します。
6. 「検知時にLINEへ送信する」をオンにします。LINEだけ使う場合はDiscordの自動送信はオフにします。

トークンとユーザーIDは起動中のみ保持し、ファイルやログには保存しません。トークンは第三者へ共有しないでください。既知の自分のユーザーIDへ送る用途では、受信用Webhookサーバーは不要です。

送るのは通知文と時刻です。音声・一致度・診断ログは送りません。自動通知は30秒間の重複送信を抑制し、失敗時の自動再送は行いません。テスト送信は自動送信がオフでも送信し、テストも契約プランのメッセージ通数に数えられます。利用可能な通数はLINE公式アカウント側で確認してください。

「LINEが送信要求を受け付けました」はAPIの受付成功を表します。ブロックや友だち登録状態、端末の通知設定によって、到着やプッシュ通知は保証されません。実際のスマートフォンでも確認してください。

公式手順: [アクセストークン](https://developers.line.biz/ja/docs/basics/channel-access-token/) / [自分のユーザーID](https://developers.line.biz/ja/docs/messaging-api/getting-user-ids/) / [公式アカウントの設定](https://developers.line.biz/ja/docs/messaging-api/building-bot/)

## 何を検知する？

マッチ成立の効果音だけを検知します。複数の確認済みサンプルから作った特徴データを使い、異なる音の重なりに対応します。

初期しきい値は **0.90**。表示される一致度は正解率ではありません。検知後30秒間は重複通知を抑制します。

別アプリを除外しても、OW内のBGM・ボイスチャットは取得音に含まれます。ゲームはバックグラウンドでも音を出す設定にしてください。

## プライバシー

ローカルの検知機能はアカウント登録、クラウド解析、音声アップロード、マイク入力を使いません。外部通知には各サービスの設定が必要です。監視した音声をファイルに保存しません。

トラブル確認のため、時刻・プロセスID・受信秒数・音量・一致度・エラー内容を `diagnostics.log` にローカル保存しますがログに音声波形や会話の文字起こしは含まれません。ログの自動送信もありません。

詳しくは [PRIVACY.md](PRIVACY.md) を参照してください。

## 動作確認と現在の制限

以下のゲーム上での動作確認は **Steam版Overwatch** で行っています。Battle.net版では検証していません。

登録に使っていない録音2本で、マッチ成立音を検知しました。一致度は約0.99と0.94です。待機開始音、ビルド画面の効果音、無音、ランダムノイズでの不検知も確認しています。

一方、確認済みの別候補1件は約0.71で検知できていません。ゲームの設定・言語・音の重なりによって見逃しや誤検知が生じる可能性があります。試用版として実際の環境で確認してください。検証値は `validation-results.json` にまとめています。

## 困ったとき

- **何も表示されない:** 「検知開始」を押し、開始受付と接続のログを確認してください。
- **音声データ待ち:** OWで音が鳴っているか確認してください。
- **受信しているが検知しない:** 5秒ごとの音量・最大一致度を確認してください。しきい値を下げると誤検知も増えます。
- **録音の再生に反応しない:** ブラウザや音楽プレイヤーの音は対象外です。OWの音のみ取得します。

## 開発

本ツールは、AI（OpenAI Codex）を活用して設計・実装・テストを進めています。開発時にAIを利用していますが、使用中の音声検知はPC内で行い、音声をクラウドAIなどの外部へ送信しません。

Python / NumPyによる周波数特徴の照合と、Windowsのプロセス別WASAPIループバックを使います。`ProcessAudio.cs` は同梱ヘルパーのソースです。ゲームへのDLL注入やゲームメモリの読み取りは行いません。ヘルパーを変更したら `build-audio.bat` で再ビルドできます。

```powershell
.venv\Scripts\python.exe -m unittest test_app test_process_audio test_discord_notify test_line_notify -v
```

[Microsoftのアプリ別音声取得サンプル](https://learn.microsoft.com/en-us/samples/microsoft/windows-classic-samples/applicationloopbackaudio-sample/)

本ツールは非公式の個人開発ツールです。
